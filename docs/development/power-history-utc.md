# Bounded power history and UTC display

The dashboard uses one explicit UTC observation window, captured before its provider read. Its typed result/session retain both boundaries; a slow operation does not move the displayed window after fetching data. The pure presenter emits every intersecting five-minute UTC bucket from the floor of the start through the floor of the inclusive end. A positive dashboard window is at most 48 hours, producing at most 577 aligned labels/values per series. Empty, leading, trailing, partial-source and common outages remain null slots; they do not compress elapsed time or connect the line across missing acquisition periods. Chart.js keeps its existing gap behavior. Dataset/label construction runs once for each history revision, independently of the faster current/freshness cadence.

`PowerInventoryConfigurationProvider` selects deterministic representative IDs in storage before loading JSON. UTC year/month/day/hour and minute/5 grouping translates on the production SQL Server provider. The last source observation in a bucket wins, with descending ID as the tie-break. MPPT selection is per requested source/bucket; battery selection preserves requested source/device/bucket streams. Battery values remain canonical in the response and are negated only for the existing battery-facing chart convention. The presenter retains configured expected PV inputs and refuses subtotals when an input is absent or source times exceed the existing derivation-skew limit. Unrelated sources cannot fill gaps.

There is no newest 5,000-row cap. At the supported 15-second cadence a 48-hour request contains 11,521 observations including both endpoints, yet normally loads only 577 MPPT JSON representatives per source. Query metadata work scales with the requested records/buckets; payload materialization/deserialization scales with selected buckets. Existing source/time and time indexes remain unchanged; no schema/index migration is needed. Each battery device has its own selected stream and chart series so device changes do not silently fill another device's gaps. Output bounds are per configured/represented stream, rather than a new global device/source limit.

Malformed JSON or invalid tracker collections are skipped and logged. A bucket can try at most the three newest candidate IDs, loading one detail per unresolved bucket in each round. Normal buckets stop after the first valid payload; worst-case detail work is three times the selected bucket count. If those candidates are invalid, that bucket remains an explicit gap even if a much older valid record exists. This bounded fallback prevents corrupt historical payloads from restoring unbounded deserialization. It preserves recent-valid fallback, while reporting exhausted buckets through a structured warning and partial/empty chart coverage. It does not silently shorten the requested window. The fixture tests cover both successful fallback and exhausted candidates.

All persisted `datetime2` power observations represent UTC. On the read/DTO boundary their `DateTimeKind` is restored with `SpecifyKind(Utc)`; they are never interpreted as the server's local clock. Provider cutoffs and freshness mappings share a captured value from the existing injected `TimeProvider`. Current source freshness and allowed clock skew retain their established rules. Historical selection ends at the explicit requested UTC end; a later sample cannot replace a sample inside the requested window. The current composition also restores UTC kinds in sourced/bank timestamps, so serialized observation timestamps carry their intended UTC meaning.

Display uses the existing `HvoDisplayTimeZone` and explicit `HvoFormat.Timestamp` timezone overload. `PowerStatus:DisplayTimeZoneId` optionally selects the display zone; absent configuration uses the established `America/Phoenix` policy and an invalid zone falls back to visibly labeled UTC. The zone appears beside the history window and the current observation timestamp. Labels use the display zone while spacing/bucketing remain UTC, preserving regular elapsed intervals across display-zone transitions. No host-local display fallback or second time framework is introduced.

Public power JSON properties/routes, incoming source timestamps, canonical source selection and electrical signs remain stable. Restoring UTC kinds and the stated display zone corrects the ambiguous timestamp behavior. Existing provider/query methods remain callable; compatible overloads carry the exact window end for the real dashboard. Legacy test doubles can forward their old method through the default interface implementation, while the production provider/query use both bounds. Refresh/disposal/retry and per-operation scopes remain owned by #404; ingest identity and immutable replay remain owned by #402/#400.

Validation includes actual SQL Server translation with a >5000-record 48-hour fixture and materialization counters; invalid payload fallback/source/device isolation; UTC and SQL-style Unspecified equivalents; injected-clock freshness; full UTC-grid/window/skew/sign tests; and actual Website Chart.js inspection of null data, skipped points, unbridged segments and proportional categorical spacing. Separate UTC and America/Phoenix host processes verify that the stored instant and explicit display label are independent of the machine timezone. No production or hardware operation is implied by these fixtures.
