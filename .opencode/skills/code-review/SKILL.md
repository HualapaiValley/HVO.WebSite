# OpenCode review adapter

Read [AGENTS.md](../../../AGENTS.md) and the [repository profile](../../../docs/development/repository-profile.md) before acting. Use [hvo-code-review](../../../.agents/skills/hvo-code-review/SKILL.md), including its full [review format](../../../.agents/skills/hvo-code-review/references/review-format.md), for every initial/correction review. Load [hvo-pr-lifecycle](../../../.agents/skills/hvo-pr-lifecycle/SKILL.md) before changing GitHub state.

Those procedures own reviewer independence, live model/settings selection, source binding, P0–P3 findings, publication/provenance and terminal verification. Resolve the actual eligible route at assignment; a configured default or historical model ranking is not executed runtime evidence. Do not edit the candidate or substitute implementer self-checks for independent review.

Use the shared [discovery and risk checklist](../../../.agents/skills/hvo-code-review/references/review-preparation.md) for supporting preparation, and current [project guidance](../../../docs/AGENT_PROJECT_GUIDANCE.md) / [CSS governance](../../../docs/CSS_GOVERNANCE.md) where applicable. Preparation candidates are hypotheses, not an approval record. Publish only the canonical review format and machine record; this adapter defines no competing review contract.
